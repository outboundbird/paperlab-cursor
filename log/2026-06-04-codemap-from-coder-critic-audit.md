# 2026-06-04 — `code_map.md` from coder output + critic audit (Option C)

Decision session (Ask mode) → build. Revises how a no-code paper's
reconstructed code becomes a learning artifact, and adds the missing
code-vs-spec firewall. Follows the two-stage coder build + GENI smoke
test ([`log/2026-06-03-two-stage-coder-design.md`](./2026-06-03-two-stage-coder-design.md)).

## Trigger

The coder's Stage-1 `README.md` (self-authored walkthrough) was an
improvement, but it duplicated what `code_map.md` already does — bridge
code to algorithm steps — in a second format authored by the wrong agent.
`code_map.md` is the implementer's artifact, generated by checking code
against `spec.md`. The user's insight: have the **implementer** produce
the walkthrough by mapping the **coder's output** the same way it maps a
git repo, just pointed at vault code instead of `upstream/`. This also
adds an independent code-vs-spec check (the code was built from the
*blueprint*; mapping it against the *spec* is a second derivation).

## The decision — Option C, audit-style

Unify the two source branches at the **mapping and review** layers, not
just the code layer:

```
PDF → dissector → spec.md
  ├─ git repo exists → implementer maps repo        → code_map.md
  └─ no repo → implementer blueprint → [critic blueprint-check]
             → coder code → implementer maps vault code → code_map.md
then both branches → critic audit (code_map ↔ spec) → critic_reviews.md
```

Both branches converge on `code_map.md` + `critic_reviews.md`. Same
format, same author (implementer maps; critic audits), same reading
experience whether or not the paper shipped code.

### Why C over A (critic intervenes)

A = implementer authors `code_map.md` over vault code and self-checks via
its own §5 gotchas. C = same authoring, but the **critic** independently
audits the result against its own spec reading.

The system's whole design is *the author is the wrong agent to audit*
(the hop-1 blueprint-check firewall). Under A the implementer is the
author of the blueprint the coder coded from; asking it to catch
divergence from spec asks it to catch its own hop-1 errors through the
same lens. C keeps the firewall: the critic is the discriminator at both
no-code hops (blueprint, then code_map), never the author.

### Why audit over gate

The final code-vs-spec check is an **audit** (durable `critic_reviews.md`),
not a transient PASS/FAIL gate. Rationale: official-code papers already
get a `critic_reviews.md`; no-code papers should too, so the branches
unify at the review layer and the user gets a durable trust artifact.
Cost: the audit schema needs a reconstructed-code variant (below).

## Two firewall edges (no-code branch)

1. **Hop 1 — blueprint.** Critic blueprint-check, pre-emission, against
   its own spec reading. (Already shipped.)
2. **Hop 2-vs-spec — code_map.** Critic audit of the implementer's
   `code_map.md` (which maps the coder's `method.py`) against spec.

The coder's invariant asserts still guard hop-2-vs-blueprint ("code
matches blueprint"); the critic audit guards hop-2-vs-spec ("code_map of
that code matches the paper"). Two independent guards on the two things
that can drift.

## Schema impact — reconstructed-code variant

`ml-code-map` and `ml-critique` both assume *official, third-party* code.
Reconstructed code needs a variant in each:

- **`code_map.md` (ml-code-map):** source is `vault_code_dir(slug)` not
  `repo_upstream_dir(slug)`; §1 header gains a "Source" field + the
  reconstructed-not-official disclaimer; code locations relative to the
  vault `code/` dir; §5 "gotchas" reframed — for vault code a discrepancy
  is **reconstruction-drifts-from-paper** (a fidelity finding), not
  authors-implemented-differently (an author-choice finding).
- **`critic_reviews.md` (ml-critique):** header sources `vault_code_dir`;
  §3 alignment reframed as fidelity-drift not author-choice; §4
  reproducibility rows that assume upstream/dataset/training are dropped
  or replaced (no upstream repo, no dataset, no training run — replace
  with "invariants pass," "seeds fixed in test_invariants").

The firewall machinery (independent spec reading, `[A]`/`[B]` discipline,
forbidden `[C]`) is reused unchanged.

## Reversals (conscious)

1. **Coder no longer authors the walkthrough README.** Reverts the
   2026-06-04 "required full README" edits. Coder Stage-1 output shrinks
   to `method.py` + `test_invariants.py` (+ optional bare run-stub). The
   walkthrough is now the implementer's `code_map.md`.
2. **Implementer runs twice on a no-code paper** — once to author the
   blueprint (blueprint mode), once to map the resulting vault code
   (general mode, vault source). The firewall worry from running the same
   agent twice is what the critic audit resolves: the audit, not the
   mapping, is the independent check.

## Path-resolution fix + GENI validation

Smoke-testing the new flow on GENI surfaced a bug that blocked the whole
no-code branch: the implementer (and orchestrator) reported "no code to
map / no upstream repo" even though the coder had already written
`method.py` + `test_invariants.py` to `vault_code_dir("GENI")`.

### Root cause

Not a missing file, path-helper, or permissions problem — a
**path-resolution gap in the agent prompts**. The prompts pointed agents
at `vault_code_dir(slug)/method.py` but never told them to resolve that
to an absolute path first. The vault is an Obsidian/OneDrive subtree
**outside the Cursor workspace**, so:

- `official` code (`repo_upstream_dir`, inside the workspace) is findable
  by relative search / Glob — which masked the gap.
- `reconstructed` code (`vault_code_dir`, outside the workspace) is not.
  The existence check failed, the agent concluded "no code," and the
  orchestrator compounded it by **refusing to delegate** to the
  implementer at all ("I already know map mode will fail").

`python -m tools.paths code-dir GENI` resolves correctly on the work
machine; the helper was never the problem.

### Fix

- **`implementer.md`** — source-detection block now resolves both
  candidates via the CLI (`upstream` + `code-dir`) before the existence
  test; the reconstructed-source navigation gains a step 0: run
  `python -m tools.paths code-dir <slug>` and read `method.py` from the
  printed absolute path (do not Glob the workspace).
- **`critic.md`** — the reconstructed audit cross-check (reading
  `method.py` / `test_invariants.py` to verify §3 fidelity findings and
  §4 rows) gets the same `code-dir` resolution instruction.
- **`ROADMAP.md`** — new Known-limitations entry "Agents must resolve
  out-of-workspace vault code via the CLI before reading," flagging the
  same residual risk for `coder` Stage-2 and `experimenter`.

### Validation (end-to-end, GENI)

With the fix, delegating to the subagents directly ran clean:

1. `implementer` (map, reconstructed) → `code_map.md` written; all
   spec §6.3 components mapped except baselines (expected); 5 fidelity
   gaps flagged (`epsilon=1.0`, generic `gamma/beta` inits, no
   val-split/early-stopping in `fit()`, 1-indexed predicate IDs,
   `zero_phi` self-loops). Firewall held (re-derived from spec, not the
   blueprint).
2. `critic` (audit, reconstructed) → `critic_reviews.md` (replaced the
   06/02 pre-code review). 5 claims; 9 `[A]` / 11 `[B]`, **0 `[C]`**; all
   5 fidelity gaps independently verified against `method.py`; 24
   invariants pass (seed 42); §4 = 4 yes / 2 partial.

This is the first full no-code pipeline run validated end-to-end:
blueprint → coder code → implementer map → critic audit, both firewall
edges exercised.
